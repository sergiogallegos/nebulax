# Owned terminal state

`nebulax-terminal` has **zero Cargo dependencies**, forbids unsafe Rust and performs no I/O. It is an experimental state engine, not a terminal application or a complete VT implementation. Its synchronous API has no runtime or scheduler requirement.

Implemented: bounded primary history, separate alternate screen (DEC 1049), primary resize/reflow and alternate crop/pad, incremental UTF-8, owned Unicode 18 extended-grapheme segmentation, explicit width policy, CR/LF/BS, cursor addressing/movement, saved cursor, origin/scroll regions, index/reverse index, CSI X and CSI K with parameter 0, pending wrap and cluster-aware erasure/overwrite. A generic bounded syntax parser feeds separate terminal semantics. Minimal status/cursor replies (CSI 5n/6n), BEL and OSC 0/1/2 title requests produce ordered typed output. Cells occupy 16 bytes on the verified 64-bit target, including a reserved style ID. A lead owns text; continuations cannot contain detached text. Width-changing selectors update ownership, cursor and wrapping together. Single-scalar cells keep their text inline; extra storage is used only for multi-scalar clusters.

`Row::cells()` exposes compact cells; `Cell::view()` gives borrowed logical content and `style_id()` currently returns reserved default zero. Public read views borrow `&self`; Rust prevents them from surviving a mutable `feed`. `finish` explicitly flushes incomplete UTF-8 as U+FFFD and closes parser/cluster state. Ending an ordinary `feed` never flushes partial input. No Ghostty or Alacritty implementation code is copied into this crate. Unicode data attribution is in [the data directory](../../third_party/unicode/README.md).

## Explicit research policies and bounds

- Grid dimensions are checked, require at least two columns and one row, and are capped at 65,536 cells per visible buffer. The caller can lower the cap. Primary history defaults to 1,000 rows and 65,536 cells, retaining at most the smaller of the row cap and cell cap divided by current columns. Both caps can be zero and have hard maxima of 65,536.
- Clusters retain up to 64 scalars, configurable downward. Further scalars in the same cluster are dropped with a diagnostic while constant-size segmentation context continues to advance. The next grapheme boundary resumes storage. This is a resource policy, not a Unicode limit.
- The syntax parser retains up to 32 parameter fields (including omitted and colon subparameters), one private prefix, two intermediates and 64 header bytes; numeric values are at most 65,535. Over-limit or malformed headers never dispatch truncated operations. OSC retains at most 1,024 bytes, including its command; malformed/oversized payloads are discarded. DCS/APC/PM/SOS payloads are discarded in constant space. This is a bounded 7-bit syntax profile, not complete DEC/ANSI conformance; see [ADR 0006](../../docs/adr/0006-bounded-parser-and-output.md).
- UTF-8 invalid sequences use maximal-subpart replacement behavior checked against Rust's lossy decoder. C0 controls still act at boundaries of malformed prefixes. UTF-8-encoded C1 controls are reported unsupported; raw C1 bytes are invalid UTF-8.
- Ambiguous width defaults to one and can be configured to two. Emoji presentation / W/F scalars are wide; Extend/ZWJ/SpacingMark/Prepend and default-ignorable scalars have no independent width. Valid VS16/VS15 pairs can widen/narrow an existing cluster. Cluster width otherwise retains the maximum contribution. This is a tested initial terminal profile, not comprehensive emoji-width or shaping conformance.
- Unattached zero-width input is discarded with `orphan_mark`. Cursor/control/escape boundaries close the extension target. Styling is unsupported, including SGR; a combining mark after SGR is therefore not attached to earlier text. This compatibility limitation remains visible.
- Editing either half of a wide cluster clears its whole owner. BS moves one column. Primary scrolling retains bounded history and reports oldest-row eviction. Partial-region/alternate scrolling or disabled history reports `scrolled_without_history`.
- Reflow joins soft wraps, preserves hard boundaries, grapheme ownership and printed spaces, and maps cursor offsets. Alternate resize crops/pads physical coordinates while also reflowing saved primary state. Every supported geometry succeeds: keep the primary cursor visible, retain preceding rows within history limits and crop following rows only when they cannot fit. Loss counters include saved primary state; cropping closes dangling soft-wrap links. Growth cannot restore discarded content. Invalid geometry remains atomic. See [ADR 0004](../../docs/adr/0004-cursor-anchored-resize.md) for the policy and exact counter meanings.
- Geometry-changing resize closes the grapheme extension target but preserves partial UTF-8/CSI input. An identical-size resize is a complete no-op. Repeated alternate entry/exit is idempotent.
- `FeedOutcome` reports consumed input bytes, output backpressure, boolean diagnostics and a whole-screen changed flag. Owned snapshots provide row versions by content comparison; edit-time dirty tracking and a public ABI remain future work. Diagnostic storage cannot grow with input length.

## Feeding input and draining output

`feed(bytes)` may consume only a prefix. Advance by `outcome.consumed`, drain `pop_output()` in order, and resume with the unconsumed suffix. A completed event waiting for space already counts as consumed input: do not replay its bytes. While that event is pending, another feed consumes zero bytes. `finish()` also reports `output_blocked` without closing input state; drain and retry it at EOF. Ending an ordinary feed never implies EOF.

The FIFO holds at most 64 events and 8,192 payload bytes, plus one completed waiting event of at most 1,024 bytes. `pending_output_len/bytes` include that waiting event. These are logical payload bounds, not process-memory measurements; the parser has its own bounded OSC buffer. `FeedOutcome::merge` sums consumed bytes and retains the latest backpressure state, while diagnostic flags accumulate.

Output variants are protocol `Reply` bytes, `Bell`, and `Title` with a target and untrusted text. The core performs no PTY writes, callbacks or native actions. Replies capture state when the query arrives. The runtime must retain partially written reply bytes, apply policy to effects, and bound its own queues. If its consumer cannot accept another event, stop popping/feeding; retain ownership of any event already popped. Never drain into an unbounded staging queue. The PTY experiment exercises this integration.

## Validation and remaining work

Run `scripts/verify` or `cargo test -p nebulax-terminal --locked`. Tests cover all 853 official Unicode 18 grapheme cases, 8,000 malformed three-byte combinations against Rust's decoder, explicit streaming/edge/edit/overflow expectations, deterministic mixed streams and inline ASCII storage. The segmentation detector is standard-conformant on that test corpus; the terminal adds the documented control/storage/width policies.

The [owned replay adapter](../../experiments/owned-replay/README.md) matches all 19 existing fixtures under 244 delivery variants with no deferrals. Twenty-one history/resize integration tests cover budgets, screen separation, reflow round trips, cursor mapping, partial input, explicit cropping, invalid-resize atomicity, extreme aspect ratios and mixed-operation delivery equivalence. An independent oracle checks 10,890 geometry/cursor/history combinations; a core unit test covers hard rows below the cursor. Styling, other VT protocols, comprehensive width compatibility, selection/text accessibility, allocator-failure behavior and performance remain unproven. This crate performs no native rendering, PTY I/O or Swift FFI; the separate experiments exercise those boundaries.

Twelve parser/output tests separately cover syntax boundaries, cancellation, malformed strings, typed output, count/payload pressure, exact resume and chunk-independent output order. The existing replay corpus remains a grid regression check, not coverage of these new protocols.

`Snapshot::capture` exports a complete owned visible frame with a two-MiB cell/text/row payload limit. UTF-8, cell roles, row versions and cursor state survive engine mutation/destruction. Consumers compare row versions to their last displayed frame. This currently copies/compares visible rows and does not change core grid storage; see [ADR 0008](../../docs/adr/0008-snapshot-worker-and-private-ffi.md). The private C handle layer separately bounds retained frames.

The `input` module supplies normal/application cursor-key and basic-key/C0 encoding on the engine owner; native callers submit key IDs rather than selecting escape sequences themselves. Extended keyboard modes remain unsupported. [ADR 0010](../../docs/adr/0010-cursor-regions-and-input-modes.md) defines margins, origin, save/restore, resize and mode-list policies. Thirteen additional core tests cover streaming, region/history boundaries, saved state, resize and row damage; PTY/native tests exercise application-key negotiation.

Compact cells directly own boxed multi-scalar tails; clearing/evicting a cell frees both its tail header and scalar buffer. No cluster arena, global directory, interning or retained free slots exist. Tail capacity is capped at 63 scalars, including clone/extend paths. Steady full-history, partial-region and reverse scrolling reuse existing row buffers. `storage_usage()` accounts for cells, row containers and live tail headers/capacity on both screens; allocator/RSS and transient resize memory are excluded. [Storage integration](../../experiments/storage-integration/README.md) compares the real baseline and compact engines; seven new tests cover layout, reclamation, row reuse, snapshots, clone growth and churn.
