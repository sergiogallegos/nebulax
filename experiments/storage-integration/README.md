# Compact core storage comparison

`scripts/storage-integration --output <new-directory>` rebuilds the baseline from commit `3217fb0` plus [baseline.patch](baseline.patch). That overlay adds capacity accounting and an example driver; it does not change terminal behavior. The current core and baseline compile the **identical driver** using pinned Rust, release mode and offline locked dependencies. Temporary baseline source/build files live under ignored `target/` and are removed after the run.

The driver feeds real terminal bytes, fills bounded history, scrolls 200 rows, captures owned snapshots, narrows/widens the grid, replaces retained text with ASCII and destroys the engine while keeping snapshots. Five workloads cover visible ASCII, ASCII history, mixed combining/emoji, dense emoji and 64-scalar clusters. Each repetition shuffles the ten variant/scenario pairs; processes run sequentially. Defaults are two warmups and ten measured repetitions: 100 samples plus 20 warmups. Tests and other measurements must not run concurrently.

Reports record container capacities including row metadata, cell buffers, boxed tail headers and tail-buffer capacity. Cluster allocations count live owned blocks, not cumulative allocator calls. Snapshots are reported separately. Allocator overhead, unused allocator arenas, RSS, transient resize peaks and native rendering are excluded. Direct ownership adds a second allocation per multi-scalar cluster; this is an explicit tradeoff, not an allocation-count win. Timing uses uncontrolled host conditions and supports no product/competitor speed claim.

The previous [synthetic spike](../storage-spike/README.md) remains unchanged as a reference design. This comparison measures the integrated engine and its directly owned cluster tails instead of that prototype's global slot arena. Content hashes, snapshot byte sizes and post-eviction zero side capacity must match across all repetitions and variants. Original replay/Unicode/cursor tests provide the broader behavioral acceptance gate.
